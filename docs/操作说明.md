## 1  系统概述

RFQ 自动老练程序通过 EPICS Channel Access 与硬件通信，自动完成射频腔的功率爬升与脉宽展宽过程，无需人工逐步调节 Drive。

**主要功能：**
- 自动调节 RF Drive，使腔体功率收敛至目标值
- 脉冲模式下功率达标后自动展宽脉冲宽度
- 支持多个功率目标依次完成，实现分阶段老练
- 实时监测真空，超标时自动暂停并等待恢复
- 故障自动复位，超过最大次数后停机报警
- 支持运行中暂停、参数热修改、恢复继续

**老练流程简图：**

```
启动 → 初始化（打开RF） → 调节功率 → 展宽脉冲 → 切换到下一功率目标（循环） → 完成
```

## 2  启动前准备

### 2.1  检查硬件状态

1. 确认 RF 系统处于可操作状态，无残留故障
2. 确认所有真空计读数正常（< 5×10⁻⁵ Pa）
3. 确认 EPICS IOC 正常运行，可读取各 PV

### 2.2  配置 config.yaml

`config.yaml` 位于程序根目录，启动前按需修改以下参数：

#### 功率目标列表（多目标模式）

```yaml
power_targets: [16, 17, 18, 22]   # 单位 kW，依次递增
```

程序按列表顺序，对每个功率目标完成一轮"调功率 → 展脉宽"，全部完成后老练结束。

> **提示：** 若设置为空列表 `power_targets: []`，则退回单目标模式，从 `AutoC_TargetPower` PV 读取目标值。

#### 真空阈值

```yaml
vacuum:
  threshold: 5.0e-5   # 单位 Pa
```

任意真空计超过此值，系统进入 `WAITING_VACUUM` 状态，等待真空恢复后自动继续。

#### 最大故障次数

```yaml
loop:
  max_faults: 20      # 超过后进入 ERROR 状态
```

### 2.3  通过 PV 设置运行参数

启动前通过控制界面或 `caput` 命令设置以下参数：

| PV 名称 | 说明 | 典型值 | 单位 |
|---------|------|--------|------|
| `AutoC_InitDrive` | RF 启动时的初始 Drive | 100 | — |
| `AutoC_PulseStart` | 脉冲模式起始脉宽 | 100 | ms |
| `AutoC_PulseEnd` | 脉冲模式目标脉宽 | 1000 | ms |
| `AutoC_PulseStep` | 每步展宽量 | 50 | ms |
| `AutoC_DriveStep1` | 功率调节大步长（误差大时） | 10 | — |
| `AutoC_DriveStep2` | 功率调节小步长（误差小时） | 2 | — |
| `AutoC_MarginLarge` | 大步长/小步长切换阈值 | 5 | kW |
| `AutoC_MarginSmall` | 功率达标判据 | 1 | kW |
| `WaitTime_Set` | 每步展脉宽前稳定等待时间 | 60 | s |

## 3  启动程序

### 3.1  启动命令

在程序根目录下执行：

```bash
python main.py
```

程序启动后进入 `IDLE` 状态，等待启动信号。

### 3.2  启动老练

```bash
caput RFQ:LLRF:Con01:AutoC_Start 1
```

系统收到信号后立即执行初始化流程：

1. 从 PV 读取参数（功率目标、脉宽参数等）
2. 识别 RF 模式（脉冲 / CW）
3. 打开 RF，设置初始 Drive，打开频率扫描与跟踪
4. RF 启动成功后进入功率调节状态

> ⚠ **注意：** RF 启动最多重试 3 次，每次间隔 2 秒。全部失败则进入 `ERROR` 状态。

## 4  系统状态说明

当前状态通过 `AutoC_Status` PV 实时更新，可在控制界面监视。

| 状态 | 代码 | 含义 | 操作员动作 |
|------|------|------|-----------|
| `IDLE` | #0 | 空闲，等待启动信号 | 设置参数后发 `AutoC_Start=1` |
| `INITIALIZING` | #10 | 正在启动 RF 系统 | 等待完成，无需干预 |
| `ADJUSTING_POWER` | #20 | 正在调节 Drive，使功率收敛到目标值 | 监视功率变化，无需干预 |
| `EXPANDING_PULSE` | #30 | 功率达标，正在按步骤展宽脉冲 | 监视脉宽变化，无需干预 |
| `WAITING_VACUUM` | #25 | 真空超标，已暂停，等待真空恢复 | 检查真空系统，恢复后自动继续 |
| `PAUSED` | #15 | 用户暂停，RF 保持运行 | 修改参数后发 `AutoC_Start=1` 恢复 |
| `COMPLETED` | #90 | 所有功率目标已完成，老练结束 | 记录数据，发 `AutoC_Reset=1` 复位 |
| `ERROR` | #100 | 超过最大故障次数或系统异常 | 排查故障后发 `AutoC_Reset=1` 复位 |
| `STOPPED` | #101 | 用户停止或程序中断 | 发 `AutoC_Reset=1` 复位后可重新启动 |

## 5  多目标功率老练

### 5.1  工作原理

在 `config.yaml` 中设置 `power_targets` 列表后，系统按以下流程循环执行：

对每个功率目标 **Tᵢ**：

1. 调节 Drive → 使功率在当前脉宽下收敛到 Tᵢ
2. 功率达标后，开始按步长展宽脉冲（PulseStart → PulseEnd）
3. 每步展脉宽前等待 `WaitTime_Set` 秒
4. 脉宽达到 PulseEnd 后，切换到 Tᵢ₊₁，脉宽重置到 PulseStart
5. 最后一个目标的脉宽完成后，系统进入 `COMPLETED`

### 5.2  示例配置

```yaml
# config.yaml
power_targets: [16, 17, 18, 22]
```

```
# PV 设置
AutoC_PulseStart = 100   ms
AutoC_PulseEnd   = 1000  ms
```

程序将依次执行：

```
16kW × (100→1000ms)
17kW × (100→1000ms)
18kW × (100→1000ms)
22kW × (100→1000ms)  →  COMPLETED
```

## 6  暂停、恢复与停止

### 6.1  暂停

在老练运行中（`ADJUSTING_POWER` / `EXPANDING_PULSE` / `WAITING_VACUUM`），将 Start 置 0：

```bash
caput RFQ:LLRF:Con01:AutoC_Start 0
```

暂停时 **RF 保持运行**，功率和脉宽维持当前值，系统进入 `PAUSED` 状态。

### 6.2  修改参数（热更新）

在 `PAUSED` 状态下可修改以下内容，恢复时自动生效：

- **通过 PV 修改：** 功率步长、裕度、等待时间等
- **通过 config.yaml 修改：** `power_targets` 列表、真空阈值等

> ⚠ **注意：** 修改 `config.yaml` 后必须通过暂停/恢复触发重新读取，程序不会自动检测文件变化。

### 6.3  恢复运行

```bash
caput RFQ:LLRF:Con01:AutoC_Start 1
```

系统重新加载所有参数（包括 `config.yaml`），从暂停前的状态继续执行。

### 6.4  中途修改功率目标列表

1. 发送 `AutoC_Start=0`，等待进入 `PAUSED` 状态
2. 修改 `config.yaml` 中的 `power_targets` 列表
3. 发送 `AutoC_Start=1`，系统重新加载列表并继续

> **提示：** 若修改后列表缩短，且当前目标索引已超出，系统自动从第一个目标重新开始。

### 6.5  完全停止

```bash
# 若正在运行，先暂停
caput RFQ:LLRF:Con01:AutoC_Start 0

# 等待进入 PAUSED 后，再次置 0 停止
caput RFQ:LLRF:Con01:AutoC_Start 0
```

系统进入 `STOPPED` 状态，RF 自动关闭。

## 7  故障处理

### 7.1  自动故障处理

程序通过 EPICS 回调实时监听以下故障信号，检测到故障后自动执行复位序列，**无需人工干预**：

| 故障类型 | 监测 PV | 自动响应 |
|---------|---------|---------|
| 弧光（Arc） | `ArcStatus_Rd` | 故障计数+1，执行联锁复位序列 |
| 真空联锁（VacInterlock） | `InterlockStatus_Rd` | 优先发真空复位，随后执行联锁和功率故障复位 |
| SSA 前向功率 | `ForwardPowerComp` | 故障计数+1，执行功率故障复位 |
| 反射功率 | `ReflectedPowerComp` | 故障计数+1，执行功率故障复位 |

### 7.2  故障计数与超限

故障累计次数在日志中实时记录。达到 `max_faults`（默认 20 次）后：

- 系统进入 `ERROR` 状态
- RF 自动关闭
- 程序停止调节，等待人工处理

> ⚠ **注意：** 进入 ERROR 后程序不会自动重启，必须由操作员排查原因后手动复位。

### 7.3  手动复位

在 `ERROR` 或 `COMPLETED` 状态下：

```bash
caput RFQ:LLRF:Con01:AutoC_Reset 1
```

复位后故障计数清零，系统返回 `IDLE`，可重新启动。

## 8  真空监控

程序持续监测以下 8 个真空计（通过 EPICS 回调）：

```
RFQ:Vac1  RFQ:Vac2  RFQ:Vac3  RFQ:Vac4
RFQ:Vac5  RFQ:Vac6  RFQ:Vac7  RFQ:Vac8
```

任意真空计超过阈值（默认 5×10⁻⁵ Pa）时：

1. 系统记录超标的 PV 名称和数值到日志
2. 立即暂停功率调节和脉宽展宽，进入 `WAITING_VACUUM`
3. **RF 保持运行**，功率和脉宽维持当前值
4. 持续检测真空，待所有真空计恢复正常后自动继续

> **提示：** 真空阈值可在 `config.yaml` 中修改（`vacuum.threshold`），修改后需重启程序生效。

## 9  老练完成

### 9.1  正常完成标志

所有功率目标的脉宽均达到 PulseEnd 后：

- 系统进入 `COMPLETED` 状态
- `AutoC_Start` PV 自动置 0
- 日志记录总故障次数和总迭代次数
- **RF 继续运行**（不自动关闭）

> ⚠ **注意：** 老练完成后 RF 不会自动关闭，操作员需根据需要手动关闭 RF。

### 9.2  完成后操作

1. 查阅日志文件，记录总故障次数和老练时长
2. 根据需要手动关闭 RF
3. 发送 `AutoC_Reset=1` 复位程序，为下次老练做准备

## 10  异常情况处理

### 程序无响应 / AutoC_Start 读取失败

- 检查 EPICS IOC 是否正常运行
- 检查网络连接，确认 UDP 5064/5065 端口畅通
- 检查环境变量 `EPICS_CA_ADDR_LIST` 是否正确设置

### RF 启动后功率长时间不收敛

- 检查 `AutoC_InitDrive` 设置是否合理
- 调整功率步长（`DriveStep1` / `DriveStep2`）和裕度（`MarginLarge` / `MarginSmall`）
- 查看日志确认是否有频繁故障打断调节过程

### 频繁弧光故障

- 减小当前功率目标或增大等待时间（`WaitTime_Set`）
- 检查腔体状态
- 若故障次数未超限，程序自动处理；超限后需排查故障再手动复位

### 真空持续超标

- 系统保持 `WAITING_VACUUM` 状态，不自动停机
- 需要停机时：发送 `AutoC_Start=0` 暂停，再发 `AutoC_Reset=1` 停止

## 11  日志文件

日志文件路径（程序根目录）：

```
rfq_auto_conditioning.log
```

日志记录内容：状态转换、功率调节过程、故障事件、真空异常、参数读取结果。

如需更详细的调试信息，在 `config.yaml` 中修改日志级别：

```yaml
logging:
  level: 'DEBUG'   # 改为 DEBUG 可看到每次 PV 读写详情
```
